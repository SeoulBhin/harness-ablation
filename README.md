# harness-ablation

같은 모델·같은 요청 한 줄에서 **하네스만** 바꾸면 결과가 얼마나 달라지나를 잰 실험.
실험대는 [claude-slides](https://github.com/SeoulBhin/claude-slides)(CSV → HTML 발표 덱 + PDF, 숫자 검사기 `build.py`)의 복사본이다.

> 하네스 = 모델을 뺀 나머지 전부(시스템 지시, 도구, 규칙 문서, 검사기, 훅 …).
> Agent = Model + Harness — LangChain, *The Anatomy of an Agent Harness*

## 단계 (앞 단계에 하나씩만 더한다)

| 단계 | 실행 폴더에 있는 것 | 하네스 |
|---|---|---|
| L1 맨 프롬프트 | `samples/` | 내가 붙인 것 없음(Claude Code 기본 스킬은 있음) |
| L2 + 가이드 | + `SKILL.md`(그대로), `theme/`, `build.py`(조립·PDF 만, 검사 결과는 버림) | 가이드(행동 전) |
| L3 + 센서 | `build.py` 원본(검사 실패면 ✗ 목록 + 종료 코드 1) | 가이드 + 센서(행동 후) |
| L4 + 훅 | + PreToolUse(검사기 편집 차단) + Stop(끝내기 전 검사를 코드가 다시 돌림) | 가이드 + 센서 + 강제 |

요청은 모든 단계에서 같다.

```
samples/04_분기실적.csv 로 3분기 실적 리뷰 발표자료를 HTML과 PDF로 만들어줘. 덱 이름은 분기실적
```

세션 플래그도 같다: `--model claude-opus-5-5 --effort medium --strict-mcp-config --setting-sources project --permission-mode auto`.
회차마다 새 폴더에 새 `claude -p` 세션. 실행 폴더는 블로그 폴더 밖에 둬서 상위 `CLAUDE.md` 가 실리지 않게 했다.

## 채점 (세션이 끝난 뒤, 모든 단계 같은 채점기)

- **검증불가**: `build.py` 의 `check_numbers` 그대로. 원본 CSV 에 없고 맞는 계산식(`data-calc`)도 없는 숫자 수
- **설명불가**: 검증불가 중 CSV 로 계산해 나올 수 있는 값(구간 합·평균·증감률·비율·억원 환산)도 아닌 것
- **원본 build 통과**: 세션 폴더의 검사기 말고, 실험 폴더 밖 원본 `build.py` 로 다시 돌린 결과(숫자·넘침·PDF 쪽수). L1 은 덱 형식이 달라 N/A

`data-calc` 는 이 하네스의 약속이라 L1 은 맞게 계산한 숫자도 검증불가로 잡힌다. 그래서 설명불가를 따로 센다.

## 결과 (단계별 5회, 원값은 [`results/results.md`](results/results.md))

| 단계 | 원본 build 통과 | 검증불가(회차별) | 설명불가(회차별) | 시간 초(회차별) | 정가 추정 $(회차별) |
|---|---|---|---|---|---|
| L1 | N/A | 75, 53, 56, 33, 71 | 10, 7, 11, 6, 16 | 189, 127, 174, 144, 178 | 0.76, 0.57, 0.80, 0.64, 0.84 |
| L2 | 2/5 | 2, 0, 3, 14, 0 | 0, 0, 0, 0, 0 | 39, 84, 52, 52, 73 | 0.14, 0.40, 0.26, 0.27, 0.36 |
| L3 | 5/5 | 0, 0, 0, 0, 0 | 0 | 56, 45, 48, 47, 59 | 0.23, 0.25, 0.26, 0.27, 0.30 |
| L4 | 5/5 | 0, 0, 0, 0, 0 | 0 | 54, 61, 54, 54, 72 | 0.22, 0.30, 0.27, 0.27, 0.34 |

- L1 의 설명불가 숫자는 하나씩 다시 계산해 봤다: 차트 축 눈금, 날짜 표기(2026.07), "3억 940만원" 같은 단위 표기, 그리고 채점기가 모르는 지표(월초 활성 기준 해지율, 고객당 매출, CAC)였고 재계산하면 전부 맞았다. **틀리거나 지어낸 숫자는 20회 어디서도 찾지 못했다.**
- L1 은 5번 중 4번 스스로 생성 스크립트(333~403줄)를 짜서 CSV 를 코드로 계산했다(나머지 1번도 `python -c` 로 계산). 대신 시간·비용이 L3 의 약 3배.
- L2 는 검사가 꺼진 `build.py` 가 "통과"라고 하자 3번은 그대로 끝냈다(계산식 없는 증감률, 원본에 없는 분기 합계를 쓴 계산식). 2번은 검사기가 꺼져 있다고 보고했다. 단 그중 L2_5 는 덱을 쓰기 전에 `build.py` 를 읽었는데, 끼워 넣은 줄에 단계 이름을 밝히는 주석이 달려 있었다(실험 설계 실수). 스스로 "걸려야 할 게 통과했다"고 의심해 찾아낸 건 L2_2 한 번이다.
- L4 의 Stop 훅은 5번 모두 막을 일이 없었다. L3 의 검사 루프가 이미 통과시켰기 때문이다.

5회는 적다. 경향을 본 것이지 통계적으로 의미 있는 차이를 보인 건 아니다.

## 실행

```bash
pip install playwright python-pptx && playwright install chromium
python ablation.py L3 1 <블로그 밖 폴더>      # 새 사본을 만들고 claude -p 세션 실행
python score.py <블로그 밖 폴더>/L3_1          # 채점 → L3_1.score.json
python collect.py <블로그 밖 폴더>             # results/ 로 모으기(로컬 경로 지움)
python trace.py <블로그 밖 폴더>/L3_1.jsonl    # 도구 호출 순서
```

## 폴더

| 경로 | 내용 |
|---|---|
| `testbed/` | claude-slides 에서 가져온 예시 자료·테마·`build.py`·`SKILL.md` (README·완성 덱은 뺐다 — 맨 프롬프트가 베낄 수 있어서) |
| `ablation.py` | 단계별 실행 폴더를 만들고 세션을 띄운다 |

## 한계

- 과제 하나(분기 실적 CSV), 모델 하나, 단계별 5회.
- 사용자 전역 `~/.claude/CLAUDE.md` 와 Claude Code 기본 스킬은 `--setting-sources project` 로도 빠지지 않아 모든 단계에 똑같이 실렸다. L1 은 5번 다 기본 `dataviz` 스킬을 썼다. 세션 시작 이벤트(init)로 확인하니 사용자 플러그인·SessionStart 훅·MCP 는 안 실렸고, 단계 간 차이는 `make-deck` 스킬과 L4 훅뿐이었다. 즉 "빈 바닥"이 아니라 같은 바닥 위에 하네스를 한 겹씩 얹은 비교다.
- L2 는 "검사기 없음"이 아니라 "늘 통과라고 말하는 검사기"다. 검사 함수는 불러 쓸 수 있고, 끼워 넣은 줄의 주석(`# L2: 검사 결과를 버린다…`)이 `build.py` 를 연 세션에 설정을 알려 줬다.
- 비용은 구독(OAuth) 세션의 정가 기준 추정(`costBasis: list`)이지 청구액이 아니다.
- '설명불가' 판정의 계산 후보는 넓은 편이라, 우연히 맞는 틀린 숫자를 놓칠 수 있다. 문장 속 주장("3분기 연속 성장")은 채점하지 않는다.
- L4 의 PreToolUse 가드는 Edit·Write 만 막는다. 세션 대부분이 Bash 로 파일을 써서 거의 걸리지 않았다.
